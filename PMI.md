# ПРОГРАММА И МЕТОДИКА ИСПЫТАНИЙ

## 1. Цель

Проверить соответствие Sales Performance Dashboard «DJI-Market» требованиям ТЗ, корректность бизнес-расчётов, работы API, интерфейса, БД, Docker-запуска и обработки граничных случаев.

## 2. Условия

ОС: Windows/Linux/macOS с Docker.

Запуск:

```text
docker compose up --build
```

Проверка UI: viewport около 1440×900.

## 3. Программа испытаний

| № | Проверка | Ожидаемый результат |
|---|---|---|
| 1 | Чистый запуск `docker compose up --build` | Frontend, Backend, PostgreSQL запускаются без ручных действий |
| 2 | Migrations | БД создаётся автоматически |
| 3 | Seed | Автоматически создаются 15–25 менеджеров, 50–100 клиентов, несколько категорий, десятки товаров, 2000–5000 продаж за ≥6 мес.; данные воспроизводимы |
| 4 | Связи БД | Manager, Customer, Category, Product, Sale, SaleItem связаны корректно; статусы `Paid/Cancelled/Refunded` работают |
| 5 | Revenue | Сумма оплаченных продаж рассчитывается корректно |
| 6 | Gross Profit | `Revenue − Cost` рассчитывается корректно |
| 7 | Margin | `Gross Profit / Revenue`; при `Revenue = 0` ошибки деления нет |
| 8 | Sales | Считается количество продаж, а не SaleItem |
| 9 | Average Check | `Revenue / Sales` рассчитывается корректно |
| 10 | Refund/Cancelled | Обрабатываются по правилу, указанному в README, одинаково во всех блоках |
| 11 | Периоды | Работают Today, 7 days, 30 days, This month, Previous month и произвольный `from/to` |
| 12 | Границы дат | Продажа на начале диапазона учитывается, за пределами диапазона — нет; граничное поведение соответствует принятому правилу |
| 13 | Previous period | Сравнение выполняется с предыдущим сопоставимым периодом |
| 14 | KPI | Отображаются Revenue, Gross Profit, Margin, Sales, Average Check, Best Manager; значения соответствуют API |
| 15 | Динамика | Revenue, Gross Profit и Sales Count корректны по дням выбранного периода |
| 16 | Ranking | Переключение `Gross Profit / Average Check`; сортировка и показатели менеджеров корректны |

| 20 | Top Products | Отображаются лучшие товары и корректно считаются Units, Revenue, Gross Profit |
| 21 | Последние продажи | Корректны дата, менеджер, клиент, товары, статус, сумма и GP |

| 23 | Server-side analytics | Фильтрация и агрегаты выполняются на сервере/в PostgreSQL; frontend не загружает все продажи для расчёта dashboard; N+1 отсутствует |
| 24 | Индексы и SQL | Связи, типы данных и индексы соответствуют аналитическим запросам; SQL EF Core переводится корректно |
| 25 | Loading | Есть initial loading и loading при смене периода |
| 26 | Error state | Ошибка API отображается пользователю, бесконечного spinner нет |
| 27 | Empty state | При отсутствии продаж отображаются понятные empty states без `NaN/Infinity/null` |

## 4. Критерий приёмки

Продукт считается прошедшим испытания, если:

- все обязательные проверки имеют результат **PASS**;
- приложение запускается одной командой;
- dashboard отображает корректные данные;
- бизнес-расчёты и фильтрация периодов соответствуют ТЗ;
- ошибки и пустые состояния обрабатываются корректно;
- автоматические тесты проходят.

Допустимые недоделки, не влияющие на основной сценарий, фиксируются в README в разделе дальнейших улучшений.
